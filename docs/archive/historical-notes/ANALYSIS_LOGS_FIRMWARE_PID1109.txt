Log findings
------------

1. Universal Analog Plugin loaded normally:
   - ABI1;
   - SDK initialise result=0;
   - transport_error=0;
   - 225 successful poll calls;
   - clean shutdown without a crash.

2. UAP did not publish the PID 1109 device:
   - dense_devices=0;
   - count=0.
   This is expected for a dedicated native build, where VID 373B/PID 1109 is
   excluded from UAP before `CreateFileW`.

3. A different backend was running at the same time:
   - protocol=madlions-a0-passive;
   - profile=madlions-a0-fw-1109;
   - usage=0001:0000;
   - samples=0 for the entire session.

4. The HallJoy MAD68 Pro R Native Stable source does not contain the
   `protocol=madlions-a0-passive` lines. The test therefore used neither the
   dedicated `HallJoyMAD68ProRNative.exe` nor another target built from those
   sources.

5. The correct firmware-specific backend must:
   - create `HallJoyMAD68ProR.log`;
   - write `backend worker start build=MAD68ProR-Native-Stable-v3.5`;
   - execute the safe `A9 -> A8 -> A9` sequence;
   - receive A0 packets and publish actual values in the `0..1600` range.
