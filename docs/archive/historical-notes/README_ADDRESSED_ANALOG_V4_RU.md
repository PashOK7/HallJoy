# HallJoy — Universal Addressed Analog v4

Эта версия заменяет модельно-зависимый backend QBZ75 на протокольный backend для клавиатур, которые действительно поддерживают проверенный 64-байтовый request/response-протокол `09 94 02`.

## Что считается совместимым устройством

Устройство не принимается только по бренду или VID/PID. Требуются оба уровня проверки:

1. HID-отпечаток:
   - usage page `0xFF60`;
   - usage `0x0061`;
   - input/output report не меньше 64 байт.
2. Безопасный capability probe:
   - корректная checksum, сумма 64 байт равна `0xFF mod 256`;
   - ответ `09 94 02`;
   - ответ содержит ровно запрошенные key ID;
   - шестибайтовые записи и правдоподобное текущее analog raw.

До успешного probe устройство не перехватывается у остальных backend HallJoy.

## Поддерживаемые профили

Backend сначала отправляет read-only запрос `09 83 00` и пытается получить карту:

```text
key ID -> USB HID usage
```

Если устройство возвращает достаточно полную карту, профиль строится динамически. Это позволяет поддерживать отличающиеся размеры и раскладки без отдельного исходного файла на каждую модель.

Если карта отсутствует или частичная, используется подтверждённая canonical-карта платформы QBZ75/AULA 84 HE. Через неё продолжают работать прошивки семейства QBZ65/QBZ75, у которых координаты стандартных клавиш совпадают.

## Что backend не делает

- не включает сервисный stream `94/00`;
- не отправляет старую регистрацию `94/05`;
- не зависит от цифрового key-down;
- не отключает polling из-за rapid trigger;
- не принимает устройство только потому, что у него VID AULA;
- не пишет каждый USB-пакет на диск.

После успешного probe используется только адресный запрос `94/02`, до девяти key ID на пакет. Команда `98/02` отправляется один раз при начале сессии, чтобы выключить устаревший last-key diagnostic mode.

## Планировщик

`addressed_poll_scheduler.*` не содержит Windows/HID-кода и работает с динамическим количеством физических позиций до 255.

Приоритеты:

1. забинженные клавиши;
2. движущиеся, нажатые и недавно отпущенные клавиши;
3. фоновый обход остальных клавиш.

В каждом пакете сохраняются два фоновых слота. Поэтому большое количество биндов автоматически распределяется по двум, трём и большему числу пакетов, но не останавливает фон.

## Сосуществование со старым Aula backend

`AddressedAnalog_Start()` запускается до `Backend_Init()` и синхронно проверяет подходящие endpoints. Старый Aula backend вызывает `AddressedAnalog_ClaimsDevicePath()` перед открытием `FF60:0061`.

- probe успешен: endpoint принадлежит универсальному addressed backend;
- probe отклонён: старый Aula backend может продолжить работу через `0x98` и прежние режимы.

Так исключаются два reader-потока на одном interrupt endpoint без жёсткого списка PID.

## Логи

В Release-сборках обычный `DebugLog_Write` отключён. Поэтому предыдущая v3 могла работать исправно и не создавать отдельного файла: `QBZ75AnalogTrace.log` появлялся только при аномалии.

В v4 используется отдельный компактный журнал:

```text
HallJoyAddressedAnalog.log
```

Он создаётся только если найден HID-кандидат `FF60:0061`. В нём записываются:

- VID/PID и HID-отпечаток;
- название продукта;
- результат capability probe;
- источник карты: `device-map`, `canonical+partial-map` или `canonical-fallback`;
- число опрашиваемых клавиш;
- сводка раз в 10 секунд: pps, потери, RTT, частоты классов и максимальный возраст данных.

Размер ограничен 2 МБ, предыдущий файл сохраняется как `.1`.

При ошибке отдельно сохраняются последние 256 транзакций:

```text
HallJoyAddressedAnalogTrace.log
```

## Ограничения v4

- одновременно универсальный backend активно обслуживает одно подтверждённое addressed-устройство;
- второе устройство остаётся доступно другим backend;
- неизвестная модель без `0x83` должна использовать canonical key ID, иначе capability probe будет отклонён;
- точные заводские endpoints калибровки пока известны только для QBZ75 W/A/S/D, остальные клавиши используют безопасную адаптивную калибровку;
- реальную совместимость каждой новой модели всё равно следует подтвердить логом `probe accepted` и движением нескольких клавиш.

## Сборка

Требуются Windows x64 и Visual Studio 2022 с Desktop development with C++.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\BUILD_ADDRESSED_ANALOG_V4.ps1
```

Результат:

```text
SEND_ADDRESSED_ANALOG_V4_EXE\HallJoy_AddressedAnalog_v4.exe
```

## Что прислать после первого теста новой модели

Достаточно файла:

```text
HallJoyAddressedAnalog.log
```

Если появился `HallJoyAddressedAnalogTrace.log`, приложить и его. `HallJoyAnalogHost.log` относится к изолированному Universal Analog Plugin и сам по себе не показывает работу native addressed backend.
