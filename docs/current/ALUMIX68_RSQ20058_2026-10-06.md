## Implementation (`redsquare_alumix68_protocol.h`, `redsquare_alumix68_backend.cpp`)

- Exact admission: `0C45:80A2`, vendor collection FF68:61 with 65/65-byte
  reports.
- Firmware gate before any depth read: command `0x12` (flash read) must return
  the exact v1.30 scan map AND a 56-byte window of the command dispatcher code
  (flash `0xE400`). A rebuild that could move the depth table changes that code,
  so the gate fails closed. On mismatch: no connection, `alumix68.firmware_unknown`
  (bit 1 = scan map matched, bit 0 = code matched) and
  `alumix68.firmware_code_head` (compact signature) are logged; the yellow
  notice "Red Square Alumix 68: unrecognized firmware" asks for the log.
- Session: five `0x16` reads (56*4 + 32 bytes) per poll of the depth table,
  read-only; no calibration, no simulation mode, no writes.
- Layout token `redsquare-alumix68` / `RSQ20058-0C45-80A2`; no built-in layout
  yet, so the default 100% layout is shown (yellow does not require a layout).
- Notice flag `RedSquareAlumix68` (268435456), title "Red Square Alumix 68:
  hardware testing incomplete".
- Test: `redsquare_alumix68_protocol_test` (identity, collection, 68 unique
  usages, sentinel slots, request/reply framing, chunk plan, scaling,
  fingerprint self-test) runs in `run_native_backend_checks.py`.
