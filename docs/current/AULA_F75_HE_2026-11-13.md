## Reviewed suitability and host implementation

Strict pinned replay completed:2 images,1280 producer cases. Execution PASS;
formal assessment NO_SELECTED_PATH. Exact inputs, own review tool and raw results
are pinned in `.local/firmware-behavior/aula-f75-exact-20261113/`. This is not a
receiver firmware dump or physical ADC/USB/timing/typing test. The bounded search
does not prove absence of other commands or behavior on later firmware.

Read-only68 is preferred because it can query each channel independently of lost
change events. The ordinary backend rejects the reviewed request echo, then tries
reversible66/FB without a calibration mode. Missing optional device info, firmware
metadata, assignment pages, unknown actions, duplicates, disabled assignments,
extra slots or layout-cache exhaustion do not veto this safe exact-device trial.
An explicit foreign remote ID does veto F75 commands. Frames must match the
manufacturer's collection/report envelope. No arbitrary firmware version allowlist.

All80 physical channels are mapped. Factory mode and live assignments use separate
physical publications so releasing one alias cannot release another.68 schedules
bound keys first and scans the remaining physical positions between bound rounds;
there is no sleep, synthetic rate cap or per-key expiration.66 reads every actual
FB report. Actual zero releases and remote/transport disconnect clear input; quiet
streams are not converted into digital or timed fake releases. The fallback
stream's coverage, missing reports and typing coexistence remain unverified on
real F75 hardware, so it is a compatibility trial, not completed support.

FB carries its stroke field.68 currentStroke uses the documented family depth
cache convention (0.01mm) and provisional3.4mm full travel; no target implementing
image was obtained to establish that getter's physical scaling. The ordinary log
explicitly marks status_scale_hardware_unverified. No learned baseline or manual
calibration is added. Range, shallow response, firmware filtering, packet loss,
crash cleanup and HUB contention remain hardware unknowns.67 is attempted after66
on normal stop/fault, including cancellation; no settings, reset or flash command
is sent. Win32 overlapped requests cancel and drain before buffers/handles die;
a separate cancellation event closes the stop-before-read race.

Two built-in exact ANSI presets derive from the manufacturer's80-key geometry;
no guessed extra analog rotary encoder. Verified model identity may show a
factory-layout preview while waiting for depth, without a connected source or
remap ownership. Live samples enable the normal source and remap path. Shared
layout tests cover preview/live/disconnect, stable render snapshots and ambiguity.

## Transport selection and hotplug

When USB and the dongle are both present, the wired collection takes priority.
A topology notification wakes the I/O worker, which checks actual candidate paths.
Appearance of a wired target while waiting on RF, or removal of the active target,
cancels and drains the old request and re-enumerates. An unrelated mouse/gamepad
notification keeps the pending read and existing depths; it does not manufacture
a keyboard disconnect or a zero release. No UI-thread HID enumeration is added.
Known metadata-access failures log the Windows error and retry discovery without
vendor commands; missing report framing is not silently treated as an open source.
A second hash-verified backup precedes this transport/lifecycle change.
