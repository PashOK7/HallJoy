## Правила продолжения

- Общение с владельцем на русском; обычный UI, логи и комментарии кода на английском.
- Перед каждой записью сверять актуальные байты/хеш цели; чужие изменения сохранять.
  Перед крупными изменениями делать проверяемый бекап с возможностью отката.
- Визуал оценивает владелец; агент проверяет код и автотесты без визуальных прогонов.
- Аналоговая глубина берётся из устройства; цифровые события и длительность
  удержания не могут её имитировать. Синтетика допустима в изолированных тестах.
- Для Keychron HE учитывать подтверждённый путь кастомной прошивки; добавление
  раскладок не блокировать повторным исследованием уже принятой основы аналога.
- Supported требует встроенной раскладки, `supported_layouts.json` и проверок
  каталога/таблицы. Смена поддержки синхронизируется с runtime, README,
  SUPPORTED_HARDWARE и живой Google Sheet с проверкой результата чтением.
- Yellow означает полный включённый путь до геймпада; исследование само по себе
  не является поддержкой. Не выдавать программный PASS за аппаратный тест.
- Тестировщику передавать один обычный HallJoy.exe, результат получать через
  HallJoy.log / Open log. Постоянное логирование необязательно; предусмотренные
  автоматические отчёты сохраняются. Ограниченный/нестабильный режим сам по себе
  не разрешает принудительное логирование.
- Обычная выдача: `build/bin/Release/x64/HallJoy.exe`. Использовать
  `tools/build_release.ps1`: сначала кандидат и проверки, затем замена точного EXE.
  Закрытие HallJoy уже разрешено; сначала штатное, при необходимости адресное
  завершение. Ранее работавшее приложение восстановить видимым/свёрнутым.
- Для обычного изменения кода: один `run_native_backend_checks.py --require-compiler`
  с действующим кешем и одна `build_release.ps1`. Не отключать кеш и не повторять
  прошедшие проверки без причины; не запускать беспричинные длительные soak-тесты.
- Публикация требует соответствующего запроса владельца. Использовать очищенный
  main, `tools/release.py` и проверку publication inputs; не возвращать удалённую
  историю/чужие vendor-материалы с неустановленным правом распространения.

17.14.7, LLVM/clang-cl, CMake, Ninja и rg. В текущем Python доступны unicorn,

таблице не подтверждён. При задаче синхронизации проверить доступный способ,

hook в Codex не предполагается; ссылки в ответах проверять и давать абсолютными.
