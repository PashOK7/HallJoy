# Сводка аппаратного журнала MAD 68 Pro R

Источник: `HallJoyMAD68ProR.log`, запуск 29 июля 2026 года.

## Идентификация

- VID/PID: `373B:1109`.
- bcdDevice: `0x0102`.
- Vendor HID path: interface `MI_01`.
- Windows HID report lengths: input `65`, output `65`; это 64-byte payload плюс report-ID byte.
- Firmware protocol endpoint topology: IF1, EP04 OUT, EP82 IN.

## Выполненная активация

В журнале подтверждена строгая последовательность:

- `A9` TX `06:22:26.528`, валидный `AA/A9` ACK `06:22:26.540`;
- `A8` TX `06:22:26.744`, валидный `AA/A8` ACK `06:22:26.751`;
- финальный `A9` TX `06:22:26.751`, валидный `AA/A9` ACK `06:22:26.761`.

Перед `A8` HallJoy дождался состояния all-keys-up и только затем разрешил baseline initialization.

## Async A0 после финального A9

- Всего в журнале: `272` пакета `A0`.
- После TX финального `A9`: `272`.
- После ACK финального `A9`: `271`.
- Получено четыре последовательных цикла по 68 уникальным физическим descriptors.
- Все четыре цикла точно совпадают с scanner order из `key_descriptor_map_final.csv`.
- Медианный интервал между соседними пакетами: `15 ms`.
- Наблюдаемый диапазон интервалов: `13..31 ms`.
- Четвёртый цикл закончился через `4.236 s` после ACK финального `A9`.
- Checksum errors: `0`.
- Malformed reports: `0`.

Это исключает объяснение потока только накопленной USB/Windows-очередью: между ACK `A8` и финальным `A9` было около 7–10 ms, а firmware ограничивает генерацию примерно одним пакетом за 15 ticks.

## Подтверждённые значения WASD

- W: `0 -> 1600 -> 0 -> 2`.
- A: `5 -> 1565 -> 0 -> 0`.
- S: `0 -> 0 -> 0 -> 0`.
- D: `0 -> 2 -> 2 -> 2`.

Показанные в логе baseline:

- W: `2394`.
- A: `2419`.
- S: `2444`.
- D: `2405`.

Наблюдение W/A подтверждает, что `A0[4..5]` меняется с физическим ходом клавиши и достигает верхней границы внутреннего диапазона.

## Что этот лог не доказывает

Нажатия W/A попали внутрь стартовых forced/catch-up проходов. Журнал не содержит отдельного нажатия, начатого спустя не менее пяти секунд после окончания этих циклов. Поэтому отдельным аппаратным тестом ещё необходимо измерить:

- post-sweep steady-state branch;
- latency W/A/S/D;
- fairness при одновременном движении нескольких клавиш;
- практическую плавность синего UI-бара и ViGEm stick/trigger.
