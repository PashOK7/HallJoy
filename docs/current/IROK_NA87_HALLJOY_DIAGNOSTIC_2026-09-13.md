## Согласовано с владельцем

Отдельный ZIP с консольным тестом отклонён. Тестировщику передаётся только
`HallJoy.exe`: обычное окно, профили и вывод в геймпад сохранены. Пользователь
нажимает клавиши по одной и вместе, видит статус завершения, закрывает окно
и присылает один `HallJoy.log` рядом с EXE. Ориентир —30–60 секунд.
Есть тестировщик обычной NA87; тестировщика ND75 нет. NA87 Pro заморожена.

## Автоматический проход

- HID-метаданные семейства0416:7372: descriptor caps, report IDs, длины,
  коллекции и версии. Vendor-команды только после M484/GK8260HERGB.
- Shared WriteFile; HidD_SetOutputReport — запасной способ при отсутствии
  успешной идентификации. После успеха оставшиеся варианты подключения не
  перебираются. Другая модель не принимается за NA87.
- Карта, capability, полный поток; затем подписка на замеченные позиции,
  группы строк и колонок, возврат к общей подписке через unsubscribe.
  Основной проход занимает около44 секунд с момента начала поиска маршрута.
- Отдельные стандартные GetInputReport/GetFeature по объявленным descriptor IDs.
  Каждый маршрут изолирован; его неудача записывается, следующий не отменяется.
  Общий бюджет ограничивает число выполненных маршрутов; пропуски отражены
  разницей snapshot_planned/snapshot_attempts и статусом с ограничениями.
- Цифровые нажатия/отпускания только0416:7372, без текстового ввода; scan code,
  flags, vkey и QPC сопоставляются с сырыми vendor-ответами того же прогона.
  Повторы удерживаемой клавиши не увеличивают полноту сбора.

Встроенные скрытые процессы запускаются из того же EXE, с явно ограниченным
наследованием handles, Job containment до ResumeThread, stop event и таймаутами.
Они передают записи по pipe основному процессу. Единственный диагностический
sink — HallJoy.log; support telemetry направлена туда же. Самостоятельные PS/CMD,
result ZIP и отдельные рабочие JSONL-файлы не нужны.

Проверка достаточности: завершился основной проход, выполнены запланированные
HID-пробы, замечены минимум8 разных нажатых и8 разных отпущенных клавиш,
хотя бы2 клавиши одновременно, лог остаётся доступен. Это достаточность
диагностического материала, а не автоматическое доказательство полной поддержки.
При недостатке данных сбор завершается к60 секундам со статусом ограничений.
Если устройства нет, заканчивается сразу. Раннее закрытие сохраняет частичный лог.

## Убрано из прежнего сценария

Нет обязательного Enter между этапами, обучения WASD по8 секунд на букву,
ручного переподключения,75-секундного первого этапа, повторного exclusive
перебора после успеха и полного чтения132 настроек, которые в исследованном
протоколе не являются текущими глубинами. Нестандартные приостановленные чтения
не возобновлялись. Прошивка, калибровка и постоянные настройки не записываются.

Неподвижное удержание и независимые глубины оцениваются по тому, какие действия
реально попали в лог. Без управляемых действий тестировщика нельзя объявлять
все физические сценарии проверенными. Unknown packets сохраняются сырыми;
ND75 envelope/диапазон0–40 используются только как явно ограниченная гипотеза.

## Проверки

MSVC build:0 ошибок,0 неожиданных предупреждений; только прежний ViGEm LNK4099.
Тест внутри итогового EXE проверяет wire, диапазон, отпускание, порог достаточности,
передачу содержимого по pipe, принудительный timeout, cooperative cancellation
и автоматическое завершение при отсутствии устройства: PASS.
Встроенный ресурс ViGEm проверен без установки: PASS.
Все доступные static/portable проверки пройдены. Общий runner остановился на
instance_guard_windows: существующий HallJoy владельца держит реальный per-user
guard, Windows возвращает5. Остальные тесты после него выполнены отдельно: PASS.
Первая попытка process_generation_supervisor дала timing assertion одновременно
со сборкой; неизменённый тест прошёл при повторном запуске.

Simulator для проверок профилей собран; runtime-тест остановлен до logger/storage
защитой от второго экземпляра, показал окно error5 и был завершён по таймауту.
Не считать это PASS, не закрывать работающий HallJoy владельца ради этих тестов.
На локальном компьютере Keychron, IROK не подключена. Причина окна не в клавиатуре:
существование guard дополнительно подтверждено read-only OpenMutex(SYNCHRONIZE).

Итоговый EXE и сохранённая копия совпадают по SHA256. Все его DLL imports —
Windows components, сторонние compiler runtime DLL не нужны. JSON-записи единого
лога проверены на синтаксис и отсутствие повторных имён полей; NUL-хвоста после
закрытия нет. Frozen Pro ZIP имеет прежний SHA256.
Evidence: `build/evidence/na87-halljoy-20260913-153824/verification.json`.
Физического NA87 и визуального прогона агентом не было.

Исходники: `src/HallJoyProject/HallJoy/irok_na87_diagnostic.cpp/.h`;
общие построители из `tools/irok_na87_diagnostic/protocol.h` и текущий
`irok_nd75_protocol.cpp`. Старый standalone-код сохранён как история работы,
но его пакет больше не передавать пользователю.
