# Исправления runtime после локального лога 2026-09-13

## Результат

Пересобран обычный HallJoy.exe с автоматической диагностикой NA87 и сохранённым
выводом в геймпад. Архив тестировщику не нужен. Интерфейс, сообщения, логи и
новые комментарии кода на английском. Исследование прошивок не расширялось.

Исправлен конкретный дефект владения дескрипторами в диагностическом UAP host:
ручное закрытие hThread из CREATE_THREAD_DEBUG_EVENT и повторное закрытие
сохранённых hProcess/hThread после ContinueDebugEvent на завершении процесса.
Числовые значения закрытых дескрипторов могли уже принадлежать другим объектам.
Теперь вручную закрываются только файлы debug events; PROCESS_INFORMATION
очищается отдельно. Правило Windows подтверждено документацией Microsoft:
https://learn.microsoft.com/en-us/windows/win32/api/debugapi/nf-debugapi-continuedebugevent

Это правдоподобно объясняет invalid handle, цикл перезапусков ViGEm и зависание
остановки в присланном логе. Дефект исходников и исправление проверены; причинная
связь со всеми симптомами конкретного аппаратного запуска требует повторного лога.

Дополнительно:

- OutputRuntime проверяет результат каждого ожидания command event. Повреждённый
  дескриптор останавливает цикл с Faulted и command.wait_failed, а не создаёт
  сотни новых поколений. Обычная работа геймпада не отключена.
- Повторные analog errors ограничены одной записью в 5 секунд независимо от
  смены кода ошибки/клавиши. Есть suppressed count. Отрицательные коды ошибок
  больше не называются улучшенным аналоговым значением. Изменено логирование,
  не правила возврата аналоговых значений. В обычном release дополнительные
  часы/атомики для сообщения fallback исключены компиляцией.
- Штатный device refresh UAP больше не считается child_failure. При штатном
  refresh/resize финальный снимок не получает exit code как ошибку здоровья.
- Внутренние типы и функции диагностики помещены в anonymous namespace.

## Публичный Discord: уточнение приватности

Владелец уточнил, что тестировщик опубликует лог в открытом Discord.
Текущий EXE функционально пригоден для диагностики, но его лог нельзя считать
обезличенным и готовым к публикации без просмотра. В реальном логе16:08
есть полный путь каталога приложения (storage legacy), raw HID instance path
Logitech (backend.spark) и отдельные HID-коды нажатых клавиш (backend.input).
Маскирование в разных каналах неполное, несмотря на privacy-текст заголовка.

При наличии NA87 модуль пишет scan/vkey/flags/released и точное время событий,
сырые RX и control_snapshot, manufacturer/product, сырой ContainerId и
стабильный path_hash. Текст не декодируется, но последовательность клавиш
может раскрыть набранное во время диагностики. Содержимое неизвестных сырых
ответов заранее не гарантировано свободным от идентификаторов.
Рекомендация передавать EXE для теста не означает одобрения публичной
публикации его необработанного лога. До публичного сценария требуется
доработать обезличивание; во время сбора нельзя вводить личный текст/пароли.
