> Уточнение владельца: прежний ZIP отклонён. Нужен обычный HallJoy.exe с работающим
> геймпадом и автоматической диагностикой на30–60 секунд, статусом достаточности данных
> и одним HallJoy.log. Пользователь просто нажимает клавиши и закрывает окно.
> Готова [интеграция в HallJoy.exe](IROK_NA87_HALLJOY_DIAGNOSTIC_2026-09-13.md).
> Всё ниже — история отклонённого формата; старый пакет не передавать тестировщику.


Владелец уточнил: есть тестировщик с обычной NA87, с ND75 — нет. Требование:
один пакет с несколькими способами обмена и сценариями, чтобы не выдавать
отдельную сборку для каждой гипотезы. Минимальный inventory этим требованиям
не соответствует и включён только как автоматический первый шаг полного пакета.

## Что собирается за один прогон

1. PnP-метаданные и HID-коллекции ожидаемого семейства0416:7372: размеры,
   report IDs, value/button caps, bit sizes, logical ranges и связи коллекций.
   Полные instance suffix/серийные номера и системный текстовый ввод не собираются.
2. Матрица проб: подходящие vendor-коллекции, report IDs из HID parser,
   WriteFile/HidD_SetOutputReport, shared/exclusive. Identity/capability ответы
   записываются полностью. Выбирается лучший подтверждённый вариант.
3. Одновременное чтение vendor-коллекций одного ContainerId с обслуживанием
   по очереди, чтобы поток одной коллекции не вытеснял ответы другой.
   Размер установленной очереди чтения запрашивается обратно и записывается.
4. После M484/GK8260HERGB: карта и штатные настройки, все клавиши,
   отдельное обучение координатам W/A/S/D; общая, выбранная, только-W,
   сменяющиеся колонки и чередующиеся группы строк. В каждом многоклавишном
   этапе есть отдельный хвост с отпущенными клавишами.
5. Карта, настройки и стандартные HID-снимки сравниваются в покое, при
   удержании WASD и после отпускания. Затем проверяются неподвижное удержание
   при переподписке, финальное отпускание и переподключение.
6. Если точная идентификация не получена, пакет продолжает стандартные чтения
   HID в покое/при удержании/после отпускания, без неизвестных vendor-команд.

Все сырые vendor-ответы сохраняются, в том числе не распознанные декодером.
Сводка использует ND75 envelope и диапазон0–40 как исследовательскую гипотезу.
Иной формат не объявляется отсутствием аналоговых данных. `last_reported_*`
означает последнее полученное значение, а не доказанное физическое состояние.
У неизвестных позиций начальное значение -1, а не фиктивный ноль.

## Стандартные снимки и ограничения

GetInputReport используется для отдельных снимков состояния, отдельно от
потока ReadFile; Microsoft не рекомендует заменять им непрерывный приём:
[HidD_GetInputReport](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/hidsdi/nf-hidsdi-hidd_getinputreport).
GetFeature читает feature report, размер берётся из FeatureReportByteLength:
[HidD_GetFeature](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/hidsdi/nf-hidsdi-hidd_getfeature).
На снимок выполняются до4 ограниченных чтений; исходные байты сохраняются.

Перед отдельными процессами снимков основная сессия закрывается, чтобы её
exclusive handle не блокировал чтения; затем идентификация проверяется снова.
Недоступный report ID или метод не останавливает оставшиеся попытки.

Vendor TX ограничен явным набором форм: identity0d, map10,
wire21/channel18/subcommands2,3,4,5. Configuration coordinates только
row0..5/column0..21; mask bits только0..5. Записи настроек/калибровки/flash,
SetFeature и произвольных команд нет. Приостановленные чтения вне штатной
таблицы в пакет не входят. Изменяется временная маска подписки, на выходе
и после аварии запускается попытка отписки. После прерывания инструкция
просит переподключить клавиатуру, поскольку успешный TX не доказывает ACK.

Пробы выполняются в дочерних процессах; есть внутренний watchdog для
блокирующих операций и внешний watchdog родителя. Необслуживаемый метод
может завершить только свою пробу. Фатальная ошибка основной сессии также
сохраняется, но не выдаётся за успешное завершение всех аппаратных этапов.
Переподключение и cleanup имеют отдельные результаты в логах.

Ограничения времени и объёма: до64 transport profiles, до16 стандартных
snapshot routes и15 секунд на группу снимков; до512 байт на сырой vendor report.
Протокольные TX используют объявленный размер64 или65 байт (дополнительный
байт нулевой). Снимки без report IDs используют0; если HID parser не даёт IDs,
дополнительно проверяются только IDs из известных output caps/SDK-правила.
Это обоснованный конечный набор проб, не перебор всех неизвестных протоколов.
Нестандартный VID/PID, другая модель или физические особенности остаются
границами этого пакета. Результаты NA87 не подменяются результатами ND75.
