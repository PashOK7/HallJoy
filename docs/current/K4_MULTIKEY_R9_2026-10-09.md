## Why the build failed earlier (root causes)
1. The pinned QMK tree (commit ee7390c3) has no `bin/` directory, so the `qmk` launcher
   does not exist. The QMK CLI is a package (`lib/python/qmk`, `milc` commands).
   Launch it as: `python -c "import sys, qmk.cli; from milc import cli; cli()" <args>`
   with PYTHONPATH=<qmk-pylib>:<qmk>/lib/python and ORIG_CWD set.
   Shim: .local/qmk-shim/qmk. Python packages: .local/qmk-pylib (pip install -r requirements.txt).
2. Build must run in MSYS2 (C:\msys64\usr\bin\bash.exe; ARM GCC in /ucrt64/bin),
   not Git Bash.
3. `make -f builddefs/build_keyboard.mk` skips the top-level Makefile, which sets
   SILENT=false; recipes then break with "syntax error near ||". Use the top-level
   target: `make keychron/k4_he/ansi:keychron`.
4. "Platform not defined" was only a symptom of the missing `qmk info` (cause 1).

## r9stray: Fn press ends the session (2026-10-10)

- Symptom: pressing Fn with HallJoy running dropped the session and re-enumerated the keyboard.
- Cause: HJO1 replies and QMK notifications share the RAW IN endpoint (`USB_ENDPOINT_IN_RAW`).
  `layer_changed_nofity()` in `keyboards/keychron/common/state_notify.c` sends a frame with
  byte0 = 0xA3 (KC_GET_DEFAULT_LAYER) on every layer change. Fn is `MO(MAC_FN)`/`MO(WIN_FN)`,
  so each press sent one. The host `Query` read that frame as the reply (`reply[0] != 0xa9`),
  the heartbeat failed, the session stopped, and the keyboard re-enumerated.
- Firmware: `state_notify.c` no longer sends layer-change, factory-reset or report-rate
  notifications. Wireless responses (lkbt51/ckbt51) are replies to module commands that
  HallJoy never sends, so they stay. Patch hunk appended to `firmware/keychron_k4_he/base.patch`
  (`git diff ee7390c3`, blob 85e072c0 verified). Build `.local/k4-r9stray-build.log`, bin 112268 bytes.
- Flash: DFU backup `.local/backups/k4-stray-flash-backup-20261010.bin` (SHA256 6cf8414b...),
  image `.local/k4-stray/k4-stray-full-256k.bin` (SHA256 624612d3...), readback match, `:leave`.
  After boot phase 0; `k4_upload_test2.py hjp2`: announced 5100, commit ready, CRC match, RESULT ok.
- Host: `KeychronOnboardClient::Query` skips up to `kMaxStrayReports` (8) packets that are not the
  reply to the request, counts them (`StrayReports()`), and logs `k4.stray_reports` when a session
  fails. Test `tests/keychron_onboard_stray_report_test.cpp` (registered in
  `tools/run_native_backend_checks.py`): one stray OK, 8 OK, 9 fails, transport failure fails.
- Gates: native checks PASS (EXIT 0); `tools/build_release.ps1` PASS, EXE installed.
- Not yet verified on hardware: the Fn press itself (no 0xA3 frame after the fix). The check is
  the owner pressing Fn with HallJoy running and `LastArrival` of the keyboard not changing.
- Open decision: lease expiry (500 ms without heartbeat) still returns the keyboard to ordinary
  mode and re-enumerates it, so a host stall during a game removes the XInput pad. Options: keep
  the pad neutral for a short grace period (PARK) before OFF, or keep the current behaviour.
  Recommendation: short grace period, because a crashed HallJoy would otherwise leave a neutral
  pad for the full 30-minute PARK lease.
