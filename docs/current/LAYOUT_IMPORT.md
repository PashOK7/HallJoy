# Полуавтоматическая подготовка раскладок из веб-драйвера

Обновление 2026-09-09: пакетный каталог из 36 вариантов, составной ISO/JIS Enter
и извлечение карт из прошивок описаны в [KEYCHRON_COMPOUND_LAYOUTS.md](KEYCHRON_COMPOUND_LAYOUTS.md).

2026-09-09. Инструмент: `tools/layout_import.py`. Это отдельный offline-инструмент
подготовки пресетов, не новая кнопка в EXE и не универсальный парсер всех сайтов.
Первый адаптер принимает распакованный JSON Keychron Launcher (`layouts.keys`)
и заводскую карту QMK. После проверки результат открывается штатным редактором
как обычный INI-пресет. Аналоговая поддержка устройства от наличия раскладки
не появляется.

## Решение владельца

Существующая K4 HE — ориентир, не эталон. Расхождения с ней не исправляются
подгонкой импортированных координат. Данные производителя могут быть точнее.
Не менять сохранённую или встроенную K4 HE автоматически.

## Как получены данные

Разобран реальный JS-бандл `main.93170c9efb96eb79.js` с
https://launcher.keychron.com/ (копия в `.local/research/layout-import-keychron`).
Функция `vendorProductId` вычисляет `65536 * VID + PID`. Экспорт `CF` модуля
50446 строит `${newStatic}device/${vpid}/json/v3.json`. `loadKeyboardJson` загружает
описание независимо от потока HID. JS не исполняли; устройств не открывали.

Официальные описания:

- K4 HE ANSI: https://launcher.keychron.com/static/device/875826752/json/v3.json
- Q1 HE ANSI Knob: https://launcher.keychron.com/static/device/875825936/json/v3.json

В описании есть геометрия и координаты матрицы, но нет заводских HID-назначений.
Для них используются официальные `info.json` и `keymaps/default/keymap.c` из
Keychron/qmk_firmware, commit `bc56b3c611dcc1a8ed9a2acb8bdc4da5e1a80c27`:

- `keyboards/keychron/k4_he/ansi/`
- `keyboards/keychron/q1_he/ansi_encoder/`

Базовый URL:
https://raw.githubusercontent.com/Keychron/qmk_firmware/bc56b3c611dcc1a8ed9a2acb8bdc4da5e1a80c27/

Полные исходные документы сохранены в `tools/tests/fixtures/layout_import`.
Это тестовые данные, не часть firmware или EXE; оригинальные copyright/license
комментарии C сохранены. Хеши входов записываются в каждый отчёт.

## Преобразование и ограничения

1. Явно выбранный слой `WIN_BASE` сопоставляется с матрицей QMK по имени LAYOUT.
2. Проверяется PID (и VID, если он есть), полное совпадение наборов матричных
   координат, уникальность и допустимость геометрии. Отсутствие VID в дочернем
   QMK info отмечается: происхождение из правильного репозитория проверяет человек.
3. `x/y/w/h` берутся из Launcher, не из текущей раскладки HallJoy и не из снимка
   экрана. Масштаб: шаг 48 x 46, зазор 6. Это выбранные размеры в пикселях HallJoy,
   а не размеры физических колпачков. Масштаб можно задать параметрами.
4. Каждый край округляется независимо от абсолютной координаты (half-up), без
   накопления ошибки ряда. Явный `Yn` сохраняет дробные смещения между рядами.
5. Неизвестные QMK-действия дают `needs-review` и только отчёт, без INI. Коррекции
   привязаны к VPID, матричной позиции и исходному токену; требуют причины.
6. Fn/RGB сопоставлены именно с дополнительными кодами текущего UAP HallJoy,
   а не выдуманными HID. Составной ISO/JIS Enter поддержан точно. Повороты,
   другие пока неописанные контуры, альтернативные варианты, пересечения
   фактических контуров и дубли HID отклоняются, а не незаметно искажаются.
7. Результат — новая папка, UTF-16 LE BOM INI и review.json. Существующая папка
   никогда не перезаписывается. Ошибка записи может оставить неполный новый
   экспорт: использовать его только после успешного завершения команды.

Для другого семейства драйверов потребуется адаптер к его структуре данных;
не требуется вручную расставлять каждую клавишу. Если источник не содержит
геометрию, её нельзя восстановить из одной матрицы или PID.

## Воспроизведение

Из корня проекта (выходная папка должна отсутствовать):

```powershell
py tools/layout_import.py --launcher tools/tests/fixtures/layout_import/k4-he-ansi.json --qmk-info tools/tests/fixtures/layout_import/info.json --qmk-keymap tools/tests/fixtures/layout_import/keymap.c --layer WIN_BASE --overrides docs/research/layout-import-k4-overrides.json --output-dir .local/layout-import-k4
py tools/layout_import.py --launcher tools/tests/fixtures/layout_import/q1-he-ansi.json --qmk-info tools/tests/fixtures/layout_import/q1-info.json --qmk-keymap tools/tests/fixtures/layout_import/q1-keymap.c --layer WIN_BASE --overrides docs/research/layout-import-q1-overrides.json --output-dir .local/layout-import-q1
py -m unittest discover -s tools/tests -p test_layout_import.py -v
```

Без `--overrides` получаем список спорных клавиш, exit code 2, без INI.
После проверки файл `Imported layout.ini` можно назвать уникально, например
`Keychron Q1 HE ANSI - imported.ini`, и скопировать в папку `layouts` внутри
HallJoy data folder. После перезапуска выбрать этот пресет в Layout editor.
Готовые примеры — `docs/exports/imported-layouts`. Пользовательские файлы и
выбранные пресеты в этой работе не изменялись.

## Результаты сравнения K4 HE

100 клавиш извлечены автоматически. Для 98 обычных клавиш коды определились без
вмешательства; Fn и RGB получили две проверенные поправки. По общим HID найдено
64 расхождения геометрии с built-in. Это не означает 64 доказанных ошибки:
часть — прежние визуальные размеры/округление, часть — отличия формы клавиш.

| Клавиша | Было в built-in | Из производителя при выбранном масштабе |
|---|---|---|
| W | X=128 | X=120 (2.5 единицы) |
| Enter | X=618, W=96 | X=612, W=102 (2.25 единицы) |
| Right Shift | X=592, W=75 | X=588, W=78 (1.75 единицы) |
| Space | W=299 | W=294 (6.25 единицы, зазор 6) |
| Numpad + / Enter | H=87 | H=86 (2 шага по 46 минус 6) |

Built-in содержит Menu (101) и PrtSc (70), а заводской WIN_BASE в этих позициях
имеет Fn и RGB. Импорт использует UAP 0x409 и 0x404 соответственно. Пользователь
мог переназначать клавиши: не объявлять его фактические настройки ошибкой и не
перезаписывать их. Импорт описывает заводскую Windows-раскладку.

## Новая раскладка: Q1 HE ANSI Knob

82 позиции из Launcher: 81 клавиша и нажатие энкодера. 80 обычных клавиш + Fn
экспортированы, нажатие энкодера явно исключено в отчёте, поскольку текущий
Q1 UAP matrix содержит KEY_NONE для него. Вращение энкодера также не моделируется.
Не подменять consumer Mute кодом keyboard-page Mute: это разные события.
Нижние стрелки Y=253, верхняя Y=207, соседний Ctrl Y=242; смещение сохранено,
а не притянуто к ближайшему ряду. Q1 отсутствовала среди built-in пресетов.

## Проверки

15 unittest-тестов PASS, включая обе реальные раскладки, неизвестные действия,
повороты/составные фигуры, варианты, матрицу, пересечения, дубли/NaN в JSON,
неверные overrides, накопление округления, отсутствие перезаписи, CLI end-to-end.
Windows GetPrivateProfileStringW прочитал все K0..K99 и Y0..Y99 из реального
экспорта с правильной кодировкой. Это проверка Windows INI API, не полный
интерактивный прогон редактора. Визуальные проверки не выполнялись; EXE не менялся.

## Установка для оценки владельцем

По запросу владельца добавлены два отдельных пресета в `%LOCALAPPDATA%/HallJoy/layouts`:
`Keychron K4 HE ANSI - Imported.ini` и `Keychron Q1 HE ANSI - Imported.ini`.
Копирование запрещает замену существующего файла. Старая `Keychron K4 HE.ini`
сохранена, неизменность проверена SHA-256 до/после. HallJoy перезапущен для
загрузки каталога; выбранная раскладка не изменялась, EXE не пересобирался.
Предыдущая запись о неизменности пользовательской папки относится к этапу
подготовки, до этого явного запроса на установку.
