## Exact 1.20 findings

- The processed `A0` report parser inputs were replayed on all 61 factory
  descriptors, seven switch types and eight depths per combination (3416 cases).
  The existing `MCHOSE Ace 60 ANSI` preset has exactly the same HID set, including
  Fn. Autoselection still needs a binding to this target once integrated.
- The standard command dispatcher routes `E0` to its default handler. This was
  replayed from the dispatch boundary, without USB or a real device. `04` and
  `05` are settings reads from `0x08017000` and `0x08017800`. `A0` as a host
  request reads stored travel settings from `0x0801A800`. The device's `A0`
  stream reports live depth through a separate producer.
- The producer at `0x0800B090` is reached through the service at `0x0800A8E8`,
  gated by bit 3 of active configuration byte 7. The `06` path calls the saved
  configuration sector writer at `0x0800CC90` and then reloads the active record.
  Its 2 KiB flash erase and program calls are at `0x08005BD8` and `0x08005BE8`.
  Calibration `A8` sets the bit in RAM but also enters the calibration state, so
  it is excluded as a normal analog subscription.

## Whole-model scope and configuration replay

Owner scope: support the stock firmware versions of Ace 60 `41E4:2101`. A tester's
installed version is one compatibility observation. No upgrade or downgrade is
part of the acceptance path. Ace 60 Pro and Ace 60X are separate USB identities.

The live legacy driver sets a minimum of 1.06. This is a driver compatibility
threshold, not evidence for binaries at every intervening version. The 1.20 image
is verified. The source for the independent 1.32 report contains no firmware
image or release assets. The old port 8881 reset the connection and an archive
listing request timed out. Public catalogs and those attempts do not establish a
complete list of stock versions.

Fresh offline replay uses the full `55` command dispatcher, synthesized settings
and explicit substitutes for the flash peripheral calls. Seven `03`/`04`/`05`
requests returned matching checksummed replies. Across 32 boot profile fixtures,
1.20 selected `current` when below the saved count and selected entry zero
otherwise. It then read the corresponding table entry and fell back to profile
zero if that entry was outside 0..3. Repeated entries do not change this behavior.
The firmware's interpretation differs from the old local heuristic. An index
outside the four-entry table is outside the demonstrated write contract.

Eight save/restore cases changed one bit in one byte of a 2048-byte modeled
sector. The firmware loaded the changed active record. A ninth case with
`settings[0] & 1` set reached an additional write to `0x08018100` after the normal
change. The latter was stopped before the extra write. The firmware's next
branch would clear that flag in saved settings. A writer cannot assume every
valid getter response implies a safe session setup.

Production direction is to select a known data path from exact USB identity,
validated read-only replies and real analog frames. Use version/build for
provenance and to distinguish incompatible saved-setting writers when necessary.
Existing streams can be decoded independently of whether HallJoy may change a
saved setting. A saved-mode activation needs a confirmed profile/writer contract,
explicit user activation, readback and a recoverable cleanup path. Verify any
additional stock image against the same criteria. No volatile subscription was
established in this review. Real typing, multi-key release under USB contention,
flash interruption recovery and behavior on other versions are still open.

Research incomplete remains accurate. No physical device writes, application
build or support-status promotion were made.
