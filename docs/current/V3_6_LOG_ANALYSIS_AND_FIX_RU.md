# Анализ аппаратных логов и исправление v3.6

## Результат теста v3.5

- два успешных сеанса с подтверждёнными ACK `A9 -> A8 -> A9`;
- `68/68` физических descriptors в каждом сеансе;
- `2914` корректных A0-пакетов суммарно;
- `unknown_A0=0`, `malformed=0`, `checksum_errors=0`, `read_errors=0`, `write_errors=0`;
- реальные аналоговые переходы наблюдались как минимум у 28 клавиш, значения доходили до `1600`;
- полный режим не включился: `steady=0`, `mode=EMERGENCY WASD`;
- в журнале не было ни одного цифрового Raw Input edge, поэтому старый proof-path не мог сработать.

## Причина

v3.5 разрешал полный режим только после корреляции A0 с Raw Input-событием. На
проверенной системе Windows видела клавиатурные коллекции устройства, но worker
не получил цифровых edge-событий. Протокол A0 при этом работал исправно.

## Исправление

После трёх ordered startup cycles и окончания 4.5-секундного forced-sweep grace
backend принимает как steady-state proof только A0-переход, который:

1. относится к известному descriptor;
2. происходит при уже имеющемся снимке 68/68;
3. происходит после forced-sweep grace и не ближе 150 ms к ordered cycle;
4. пересекает индивидуальный actuation threshold;
5. имеет delta не менее 64 единиц, чтобы отфильтровать idle Hall noise.

На предоставленном журнале первое подходящее доказательство — переход W
`285 -> 474` при threshold `350` примерно в `18:42:00.764`. v3.6 в этой точке
переключился бы из Emergency WASD в Full и опубликовал все 67 HID-клавиш.
