Architecture selection
----------------------
Three options were compared before code:

1. Reuse analog-host supervisor as-is: rejected because it is UAP-specific and
   starts the child before job assignment.
2. Extract and migrate analog-host immediately: rejected for F1 because it
   changes a qualified UAP route while the common primitive is still unproved.
3. New reusable generation owner/state machine, proved against a fake child:
   selected. It allows later adapters without mixing ViGEm or UAP behavior into
   the ownership proof.

The full comparison is retained in
docs/v1.4/PROCESS_GENERATION_SUPERVISOR_DESIGN_2026-08-22.md.

Production contract
-------------------
- one non-copyable owner retains process/job handles until confirmed reap;
- per-generation job uses JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE;
- child creation uses CREATE_SUSPENDED and an explicit
  PROC_THREAD_ATTRIBUTE_HANDLE_LIST;
- AssignProcessToJobObject succeeds before ResumeThread, so application code
  cannot execute outside the generation job;
- ready/progress observations must match the expected PID and generation;
- startup, progress, graceful-stop and hard-reap deadlines are distinct;
- failed reap retains ownership and makes replacement restart-unsafe;
- the module contains no ViGEm dependency and runs outside realtime.

-------------------------

Covered cases:
- normal ready/progress and cooperative planned stop;
- exit before ready;
- never ready -> startup timeout -> job termination/reap;
- ready then no progress -> progress timeout -> job termination/reap;
- ignore stop -> graceful deadline -> job termination/reap;
- exit after ready with exact child exit 77;
- wrong generation -> protocol violation -> termination/reap;
- child-reported fatal error 0x2468 -> typed child fault -> termination/reap;
- non-inheritable handle and missing executable fail launch without poisoning
  the next generation;
- an inheritable decoy event omitted from the explicit list remains unsignalled
  even if the same numeric value is valid for an unrelated child object;
- the same supervisor object runs 1,000 additional sequential generations;
  every result is restart-safe, max active children is one, and each PID is
  confirmed non-live before replacement.

After the full suite, Win32 process enumeration found zero live fake children.

Boundary / next gate
--------------------
These EXEs were not promoted or sent to users. The module compiles in
production but is not routed from backend.cpp. F1 proves the generic primitive;
it does not yet prove early HallJoy.exe self-host dispatch. The next package
must add --halljoy-vigem-output-host with fake transport and exercise this same
owner through the real HallJoy executable before any ViGEm call moves to child.
