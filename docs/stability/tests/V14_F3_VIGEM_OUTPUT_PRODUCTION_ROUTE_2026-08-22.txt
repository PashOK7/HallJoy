Decision
--------
Selected one self-hosted child process as the sole production ViGEm owner.
Rejected patching the legacy in-process worker because a blocked
vigem_target_x360_update would remain inside HallJoy. Rejected a temporary
dual runtime because it would admit overlapping owners and require a second
migration.

Source/result boundary
----------------------
- backend.cpp contains no direct ViGEm client/target/update call and no legacy
  output thread, mailbox, closeable wake or reconnect owner.
- realtime publishes only a complete configured-pad snapshot through the
  bounded process channel.
- publication admission closes before every planned child stop or force/reap;
  any already-admitted producer drains after reap and before mapping reuse.
- a replacement generation starts only after the predecessor is reaped.
- child lifecycle identity remains valid after parent publication admission is
  closed, allowing truthful neutral/remove/completed-stop acknowledgement.
