HallJoy V14 R0 ViGEm wake close/use old-bug oracle
Date: 2026-08-22
Risk: HJ-V14-P0-005
Classification: deterministic legacy production-path RED oracle

Purpose
-------
Prove the exact legacy ownership violation before replacing the in-process
ViGEm output worker. The simulator-only injection does not model a second
algorithm: it pauses the real realtime publisher after it has copied the real
legacy wake HANDLE, then the real UI-owner recovery path executes
VigemOutput_Stop -> close -> Vigem_Create -> VigemOutput_Start. The publisher
resumes only after replacement resources exist.

Observed ownership sequence
---------------------------
1. Generation 1 wake was created as handle 0x284; its output thread was 0x27C.
2. The realtime publisher copied wake 0x284 and paused before SetEvent.
3. The UI owner joined generation 1, then successfully closed thread 0x27C and
   wake 0x284.
4. Generation 2 created wake 0x29C and reused thread handle value 0x27C.
5. The paused publisher called SetEvent on stale generation-1 value 0x284.
6. SetEvent returned success even though 0x284 was not HallJoy's current wake
   object (replacement_is_current_wake=0). The stale numeric value had already
   been rebound to an event object (stale_value_rebound_to_event=1).

This is stronger than an ERROR_INVALID_HANDLE observation: the legacy race can
silently signal a foreign event object and report success. Therefore checking
SetEvent's return value, making the HANDLE atomic, or accepting a clean process
exit cannot repair the ownership contract.

Target contract and current verdict
-----------------------------------
The target process architecture keeps the parent publisher wake alive across
all child generations and rejects publication after its output generation is
disabled. The runner requires target-safe and stale-generation-rejected
markers. The legacy implementation intentionally fails those requirements, so
the O1 gate remains RED until the production route is switched to the new
supervisor/channel and the same oracle becomes PASS.
