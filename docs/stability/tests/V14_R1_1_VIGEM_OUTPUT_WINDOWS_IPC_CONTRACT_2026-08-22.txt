Why R1 was reopened
-------------------
The initial portable claimed-slot test was useful but insufficient for the
final cross-process contract. R1.1 corrects three foundation issues before a
supervisor is built:

1. Windows shared-control transitions now use documented Win32 Interlocked
   operations rather than relying on std::atomic_ref across processes.
2. A publisher lease closes the disable-versus-in-flight-publication window;
   the non-realtime supervisor can wait for publication quiescence before
   retiring a generation.
3. Child-written health fields are explicitly telemetry. Parent-authoritative
   restart/lifecycle state is not writable by the child.

Windows process proof
---------------------
The production channel implementation is linked into a self-spawning Windows
test executable. The parent creates unnamed inherited mapping/wake/stop
objects. A first child receives a wrong nonce and exits with code 41 before
touching the data plane. A valid child then consumes 100,000 complete four-pad
snapshots and publishes the exact final applied sequence. The parent disables
the generation, verifies publisher quiescence, requests stop, reaps the child
and exits 0.

Cross-process status and progress observations use Interlocked reads; the test
does not create a C++ data race while proving the protocol. If a test-owned
child misses its deadline, the harness terminates and reaps that exact process
before closing IPC objects, preventing a leaked survivor from being hidden by
an assertion.

Boundary
--------
This proves the ABI/data-plane foundation, not service recovery and not a
release artifact. The proof fixture currently uses broad test-only inheritance;
the production supervisor must use an explicit PROC_THREAD_ATTRIBUTE_HANDLE_LIST,
a job object, hard deadlines and zero-overlap generation ownership. No user EXE
was produced or distributed from this stage.
