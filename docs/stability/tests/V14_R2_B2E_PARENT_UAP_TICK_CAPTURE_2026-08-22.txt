Defect found
- Production could read each bound UAP key through a separate parent call.
- Each call was coherent, but one controller frame could mix adjacent analog-
  host publications.

Decision
- Counter-matched separate dense/V2 reads retain an ABA window.
- V2-only side capture leaves the qualified comparison on another generation.
- Immediate V2 route replacement removes the rollback oracle too early.
- Selected: one parent transaction containing publication metadata, aggregate
  dense, per-device dense and optional Provider V2. See D-069.

Production boundary
- Backend_Tick captures once and uses only that dense compatibility plane for
  standard UAP keys throughout the tick.
- Provider V2 remains read-only and is not consumed by configured mapping.
- Dense remains valid when V2 is absent. Complete capture failure retains the
  old analogue per-key fallback.
- No digital correlation, runtime learning or shadow ViGEm publication exists.
