Rejected evidence mechanisms
- Continuous production log: permanent I/O/noise and no session verdict.
- UI/screenshot only: no durable session identity or finalization.
- Hidden partial backend: not the normal configured application lifecycle.
- Direct counter export: idle/repeated/reset/stale evidence can false-pass.

Selected contract
- Startup removes stale final/temp reports and atomically writes a flushed
  finalized=0 INCOMPLETE report with a new session ID.
- Normal post-logger shutdown atomically finalizes the report.
- Crash or poisoned immediate process exit cannot finalize PASS.
- Process counters are monotonic and require exactly one Backend_Init.
- PASS policy: app exit 0; Provider V2 available; >=1000 eligible ticks;
  >=1000 matched reports; >=100 unique UAP sample generations; <=1%
  unavailable ticks; zero digital fallback, curve mutation and mismatch.
- Duration is recorded as informational only. The original 60-second boundary
  was removed because a 59.9/60.0-second cliff proves neither equality nor
  stability; stability is a separate soak/reconnect/fault-injection gate.
- Every V2-backed configured controller field must reach Provider V2 raw >=0.5
  and a non-neutral mapped shadow output. It then remains latched pending release
  until all V2 raw bindings and that shadow field are neutral. Partial return,
  mouse/native input and Windows digital events cannot satisfy this proof alone.
- Coverage is independent for 4 pads x 7 fields using bit pad*7+field.
- Any mismatch is FAIL. Missing proof is INCOMPLETE. Only complete proof is PASS.
- Backend_Tick performs no report file I/O.
- production_route=dense_compatibility; shadow_submitted_to_vigem=0.
