SELECTED ARCHITECTURE
- Parent-owned variable section per plane generation.
- Parent retains only a non-inheritable FILE_MAP_READ handle and view.
- Child alone inherits one read/write section handle through
  PROC_THREAD_ATTRIBUTE_HANDLE_LIST.
- Parent closes its transient writer handle immediately after CreateProcessW.
- Child publishes into two independently committed slots.
- Capacity replacement occurs only after the prior child is fully reaped.
- Shrink reuses sufficient allocation; growth creates a new generation.

REJECTED ALTERNATIVES
- Larger fixed arrays: move the capacity cliff and retain excessive rights.
- Resizable monolithic SharedState: Windows mappings do not resize in place and
  control/health/payload lifetime remains coupled.
- Pipe/RPC per snapshot: extra copy, queue/backpressure and wake boundary.
- Product singleton or immediate exclusive HID: broader compatibility changes
  are not justified by a physical-test isolation defect.
- Digital-key correlation/relearning: forbidden activation-depth delay and a
  protocol error would be hidden.

READ-ONLY FAILURE FOUND AND CORRECTED
The first exact EXE reached the new plane and then failed with 0xC0000005 in
AnalogHostClient_CaptureProviderV2PlaneHeader. The commit recheck used
InterlockedCompareExchange64 as if it were a read. That API is a
read-modify-write and faults on the deliberately read-only parent view. The
recheck now performs one aligned volatile read between memory barriers. The
static audit rejects the former const-cast/RMW pattern, and the real Windows
process regression captures through the read-only view.
