# RM-19 migration and factory-reset recovery (2026-09-06)

Migration is intentionally copy-only: the legacy source is never modified;
each backup and destination copy is atomic, pre-existing destination files are
preserved, and the validated completion marker is written last. On a later
start an incomplete migration repeats safely: existing backup copies must
match the immutable source, while already-present destination files are kept.

Factory reset uses the opposite operation—write-through moves into a named
backup—but now has an explicit interrupted-generation path. A validated reset
marker owns its random backup leaf. If the process ends after the backup tree
was created or after any target move, the next start validates the same plain
backup tree and resumes the remaining targets. It never treats that owned tree
as an unrecoverable `ERROR_ALREADY_EXISTS` collision.

For an interrupted reset, a subsequent transient failure preserves the marker
and backup tree rather than attempting to roll back an unknown earlier
generation. The next launch can retry. A resumed directory is accepted only if
its live counterpart is empty (the expected freshly-created state); reparse
points, type changes, nonempty live directories, inaccessible paths, and other
unexpected topology are rejected fail-closed. The marker is removed only after
all target moves and fresh directory creation complete.

This leaves the portable simulator runtime gate honestly pending because it
would launch HallJoy while the user may be gaming. Structural and source-only
syntax checks passed; no HallJoy runtime, HID, controller, output child, or
ROG diagnostic was started.
