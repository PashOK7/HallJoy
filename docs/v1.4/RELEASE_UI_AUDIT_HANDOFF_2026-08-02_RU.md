## Зафиксированные дефекты

### UI-01 / P1 release blocker: интерфейс мерцает от аналогового ввода

Воспроизведение: открыть HallJoy и нажимать аналоговые клавиши на Irok MG75
Max. В интерфейсе появляется заметное мерцание; особенно хорошо оно видно на
строке вкладок.

Факт из кода: `KeyboardUI_OnTimerTick` потребляет dirty-биты аналогового ввода
и инвалидирует owner-draw окна клавиш. Рядом существуют несколько независимых
путей `InvalidateRect`/`RedrawWindow`, смешение кэшированных и некэшированных
поверхностей и родительский owner-draw. Точная цепочка, которая задевает вкладки
или оставляет фоновые промежутки, пока **не доказана**. Нельзя считать любой из
этих путей установленной причиной без paint/invalidation trace.

Требуемый результат: физический аналоговый ввод может обновлять только реально
изменившиеся динамические области. Строка вкладок, фон страниц и статические
контролы не должны перерисовываться или визуально мигать. Проверить все шесть
вкладок, разные частоты UI refresh, удержание нескольких клавиш, быстрое
нажатие/отпускание и ввод во время прокрутки.

### UI-02 / P2 visual blocker: Factory reset выглядит чужеродно

Наблюдение: слева внутри кнопки видна большая ярко-красная полоса. После клика
появляется грубый пунктирный прямоугольник фокуса.

Причина подтверждена: `Global_DrawActionButton` отдельно рисует `accent` шириной
четыре DPI-масштабированных пикселя, а для `ODS_FOCUS` вызывает стандартный
`DrawFocusRect`.

Требуемый результат: убрать отдельную левую полосу. Сохранить доступный
клавиатурный focus state, но оформить его тем же скруглённым/тематическим
рендерером, что и кнопка, без стандартного GDI-пунктирного прямоугольника.
Проверить idle, hover, pressed, keyboard focus, disabled и DPI 100/125/150/200%.

### UI-03 / P1 correctness: telemetry в Configuration визуально устаревает

Воспроизведение: открыть Configuration и наблюдать debug/telemetry при вводе.
Текст не обновляется. После наведения мыши на `HE poll mode` или `Rows` внезапно
показываются свежие значения.

Причина подтверждена: `Config_DrawCustomControls` читает
`BackendAnalogTelemetry` только при отрисовке кэшированной поверхности.
Изменение telemetry не вызывает `Config_MarkSurfaceDirty`; hover custom-control
вызывает его и случайно обновляет весь кэш.

Требуемый результат: видимая live-информация обновляется по изменению данных с
ограниченной частотой и без full-page repaint. Невидимая страница не должна
опрашиваться или перерисовываться. Добавить тест, доказывающий обновление без
движения мыши и отсутствие перерисовки при неизменившемся snapshot.

### UI-04 / P1 UX: HE poll mode и Rows не являются combobox

Причина подтверждена: это нарисованные вручную `Config_DrawCustomCombo`
прямоугольники. `Config_HandleCustomControlsMouse` не открывает список, а
циклически меняет значение по каждому клику. У них нет нормального dropdown,
клавиатурной навигации и ожидаемой семантики combobox.

Требуемый результат: заменить оба элемента настоящими тематическими combobox
из уже используемой системой HallJoy (`PremiumCombo` либо единый новый control,
если аудит докажет необходимость). Должны работать список вариантов, мышь,
клавиатура, focus, DPI, скроллинг страницы и сохранение выбранного значения.

### UI-05 / P2 information architecture: diagnostics продублированы

Backend/debug telemetry одновременно находится в Configuration и Gamepad
Tester. Из-за этого настройки смешаны с диагностикой, а одинаковые сведения
имеют разные механизмы обновления.

Требуемый результат: одна каноническая live-diagnostics область. Предпочтительное
направление для аудита — объединить analog/backend telemetry с Gamepad Tester,
а в Configuration оставить настройки, два настоящих combobox и только краткий
пользовательский статус, если он действительно нужен для настройки. Не удалять
полезные диагностические поля до составления таблицы соответствия, чтобы не
потерять данные для Aula, UAP/Soup, SparkLink и остальных native routes.

## Обязательный аудит с нуля

1. Составить карту HWND/owner-draw/custom-surface для всех шести вкладок и их
   родителей: кто владеет фоном, кэшем, invalidation и double buffering.
2. Инструментировать `WM_PAINT`, `WM_ERASEBKGND`, `InvalidateRect` и
   `RedrawWindow` во время физического аналогового ввода. Зафиксировать HWND,
   регион, причину и частоту; диагностический код не должен попасть в release.
3. Проверить, что динамическая модель обновляет только изменившийся регион и
   что скрытые вкладки не выполняют live repaint.
4. Инвентаризировать все элементы, которые только выглядят как стандартные
   controls. Проверить mouse/keyboard/focus/accessibility/DPI/scroll behavior.
5. Составить таблицу всех diagnostic/telemetry строк в Configuration и Gamepad
   Tester, выбрать одно место и один snapshot/update pipeline.
6. Провести визуальную матрицу: 100/125/150/200% DPI, минимальный и обычный
   размер окна, все вкладки, idle/hover/focus/pressed/scroll, физический Irok.
7. После исправлений повторить полный build/runtime gate, но не объявлять UI
   Verified до ручной приёмки владельцем на собранном `HallJoy.exe`.

## Критерии закрытия

- ноль видимого мерцания на вкладках и статических областях при аналоговом вводе;
- ноль случайных full-page/full-tab invalidation от изменения одной клавиши;
- live telemetry обновляется без hover и замирает при неизменных данных;
- `HE poll mode` и `Rows` являются настоящими тематическими combobox;
- diagnostics представлены один раз и ни одно route-specific поле не потеряно;
- Factory reset соответствует общему дизайну во всех состояниях и сохраняет
  заметный, но аккуратный keyboard focus;
- ручная визуальная приёмка владельцем и автоматические regression gates PASS.

Физические MAD68 HE/UAP и Aula проверки остаются отдельными release blockers и
не закрываются этим UI-аудитом.
