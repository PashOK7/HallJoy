# HallJoy — результат перестройки структуры, 2026-09-06

Статус: структурный пакет завершён; обычная и диагностическая сборки проверены.

## Выполненные изменения

- Единый build root: объекты и EXE разделены по variant/configuration/platform.
- Один обычный пакет build/release; build/output больше не создаётся сборщиком.
- Обновлены runners, diagnostic builders, resource path, CI artifact path и
  проверки документации/упаковки; runtime-алгоритмы не переписывались.
- Плагин Sun компилируется из подготовленного рабочего дерева build/obj/UAP.
  Pinned Soup/Sun находятся в .cache; editable overlays остаются в third_party.
- Portable/sanitizer компиляции направлены в build/obj/portable-tests.
- 16 документов распределены по назначению с redirect notes на старых местах:
  десять из src/HallJoyProject и шесть из прежнего docs/current.
- Введены текущая инструкция, единый индекс документации и проверка структуры:
  `python tools/check_project_layout.py` (без запуска HallJoy).
- Сохранение пользовательских данных при обычной упаковке: скрипт заменяет
  только четыре принадлежащих ему файла, не удаляет содержимое release целиком.

Полная исходная копия: .local/backups/structure_20260906_122303/snapshot,
4712 файлов, каждый проверен SHA-256 относительно оригинала. CSV manifest и
пооперационные moves-*.csv лежат рядом. Перенос не означает удаление содержимого.

в build и не пересекаются. Доказательство:
`build/evidence/structure-20260906/msbuild-paths.json`.

содержала wooting_analog_common.lib. Обе библиотеки .lib/.a на самом деле нужны:
main.cpp подключает их через #pragma comment. Они сохранены как входные файлы.
Изолированная сборка обеих ABI DLL плагина после исправления завершилась с кодом 0.

## Границы

Не запускались обычный HallJoy, игровые smoke и тесты с клавиатурным/геймпадным
вводом. Изолированные portable tests используют fake transport; ABI self-test
официальной сборки может читать HID, но не создаёт игровой вывод. Проверка
встроенного установщика только проверяет ресурс/подпись и не устанавливает драйвер.

Структурный пакет не закрывает весь архитектурный Roadmap, не доказывает отсутствие
остальных ошибок и не присваивает новый hardware PASS. Sayo auto-learning и буквы
сохранены; спорное продуктовое поведение требует вопроса владельцу. Discord RM-37
по-прежнему последняя, пока не реализованная feature-карточка.

Старые EXE/артефакты/логи/бекапы сохраняются по таблице переносов, не удаляются по
возрасту. Освобождение места не является целью этой операции: полная резервная
копия увеличивает занимаемый объём. Программные исходники не дробились на новые
модули; это отдельная архитектурная работа.
