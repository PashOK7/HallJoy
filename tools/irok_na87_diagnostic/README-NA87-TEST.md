# Расширенный тест обычной IROK NA87 Mag

Это отдельный диагностический инструмент HallJoy. Он собирает сведения о
протоколе и глубинах нажатия; виртуальный геймпад не создаётся.
Нужны Windows10/11 и один запуск одного пакета, обычно 6–10 минут плюс время на инструкции.
NA87 Pro — другая ветка, этот пакет предназначен для обычной NA87.

## Запуск

1. Распакуйте весь архив в отдельную папку, например на рабочем столе.
2. Закройте HallJoy, официальный драйвер IROK и веб-конфигураторы.
3. Подключите одну обычную NA87 кабелем USB в проводном режиме.
4. Запустите `START-NA87-TEST.cmd`. Python и отдельная установка Visual C++
   не нужны. Права администратора штатно не требуются.
5. Следуйте инструкциям в окне. Enter начинает этап; завершение этапов
   автоматическое. Сигнал означает «отпустить все клавиши».

Клавиатура используется как обычно: настройки, калибровка, раскладка и прошивка
не записываются. Меняется только временная подписка на сообщения о глубинах;
в конце инструмент выполняет отписку. При прерывании теста переподключите USB.
Если программа заблокирована Windows, сохраните сообщение об ошибке; менять
системные параметры безопасности для теста не нужно.

## Что выполняется за один запуск

- Инвентаризация USB/HID-коллекций и размеров сообщений, без серийных номеров
  и сбора текстового ввода.
- Автоматические пробы подходящих vendor-интерфейсов, объявленных report IDs,
  двух способов отправки и двух режимов доступа. Ошибка одной попытки не
  останавливает остальные; зависшая попытка имеет отдельный таймаут.
- Одновременное чтение подходящих vendor-коллекций того же устройства, чтобы
  сохранить ответ, пришедший через другую коллекцию.
- Проверка идентификации обычной NA87 и ответа о возможностях. Если точная
  идентификация не получена, все ответы и причины неудач всё равно сохраняются.
- Чтение карты и штатных настроек в покое, при удержании WASD и после отпускания.
- Стандартные HID-снимки GetInputReport/GetFeature в тех же трёх состояниях.
  Если основная идентификация не удалась, этот путь всё равно проверяется;
  неизвестные vendor-команды при этом не отправляются.
- Общая подписка и нажатие всех клавиш; отдельное обучение координатам WASD.
- Сравнение общей подписки, выбранных клавиш, только W, сменяющихся колонок
  и двух групп строк. Проверяются одновременные удержания и отдельные отпускания.
- Повторная подписка при неподвижном удержании и финальное отпускание.
- Переподключение с повторной идентификацией и короткой проверкой WASD.

На этапе всех клавиш нажимайте модификаторы отдельно. Ctrl+C прерывает тест,
поэтому не используйте сочетания клавиш во время этого этапа.
Если обучение одной клавиши не получилось, инструмент предложит повторить
его внутри этого же запуска. Часть сценариев адаптируется к полученным данным.

## Что прислать

После завершения рядом с программой появится **один архив `NA87-results-….zip`**.
Пришлите его целиком. Даже сообщение «устройство не найдено» или неудачная
проверка протокола даёт полезный отчёт — отдельную сборку для этого не нужно.

Допишите точное название модели на корпусе/коробке, режим подключения и
возникали ли проблемы с обычным вводом. Если версия прошивки не появилась в
отчёте, приложите её значение из официального драйвера после окончания теста.
Версия драйвера Windows не равна версии прошивки клавиатуры.

Если запуск был прерван и ZIP не появился, сохраните папку `NA87-results-…`:
в ней остаются уже записанные данные. Не удаляйте её перед повтором.

## Как понимать результат

Успешное завершение означает сбор данных, а не доказанную поддержку аналога.
Сырые сообщения и времена сохранены для проверки неизвестных особенностей
NA87. Диапазон 0–40 и текущий декодер взяты из ND75 как исследовательская
гипотеза; значения другого формата тоже остаются в логах. Последнее ненулевое
значение в отчёте не доказывает физическое удержание клавиши.

Не выполняются прошивка устройства, запись настроек, калибровка, произвольные
команды или чтение за пределами штатной таблицы. Запросы протокола используют размер64 или65
байт из HID-описания; 65-й байт заполняется нулём. Сырые vendor-ответы
и стандартные снимки сохраняются полностью, до512 байт согласно дескриптору. Это ограниченный набор обоснованных проб, а не обещание
перебрать любой неизвестный протокол.
